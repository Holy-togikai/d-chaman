# safety.md — 安全のきまり

## 1. 人間の承認が必要な操作

**実行する前に止まって、人間に聞いてください。** 勝手にやってはいけません。

| 操作 | このアプリでの具体例 |
|---|---|
| メール・DMの送信 | 問い合わせへの返信、テスターへの連絡 |
| SNSへの投稿 | アプリの告知 |
| 購入・決済 | Apple Developer Program（年間 $99）の支払い、有料APIの契約 |
| データの削除 | ブランチの削除、`git reset --hard`、実機アプリの削除、記録データの消去 |
| **本番環境への反映** | **App Store Connect へのアップロード、TestFlight の配信、審査提出** |
| 権限の変更 | 証明書・プロビジョニングの操作、GitHub の権限変更 |
| 顧客への連絡 | レビューへの返信、サポート対応 |
| 法的な同意 | 利用規約への同意、ライセンスの受諾、**国土地理院への申請** |
| **PRのマージ** | main への取り込み |
| 強制プッシュ | `git push --force` |

**承認は一回ごと。** 「前回マージしていいと言われたから今回も」は通りません。

### 承認の取り方

「◯◯してよいですか」ではなく、**何が起きるかを具体的に**言ってから聞いてください。

> PR #11 を main にマージします。8ファイル・326行の追加です。マージ後、
> ブランチ `feature/schedule-basis` は削除されます。進めてよいですか。

## 2. 絶対に行ってはいけない操作

承認があってもやりません。人間自身にやってもらってください。

- **秘密情報を文書やコードに書く**（APIキー、パスワード、証明書の中身、個人情報）
- **Apple ID のパスワードや二段階認証コードを入力する**
- **`git push --force` を main に対して行う**
- **他人のアカウントで操作する**
- **地理院タイルの出典表示を消す**（利用条件違反）
- **利用者の位置情報・記録データを外部へ送る**

### 秘密情報について

**このアプリは現在、APIキーを一切使っていません。** 地理院タイル、Open-Meteo、
MapKit、標高API のすべてがキー不要です。これは意図した設計で、**維持してください。**

キーが要るサービスを足したくなったら、まず人間に相談を。キーは `.gitignore` した
ファイルか環境変数に置き、**指示ファイルには絶対に書かない**でください。

## 3. 失敗したときの戻し方

| 状況 | 戻し方 |
|---|---|
| 編集中でまだコミットしていない | `git checkout -- <ファイル>` |
| コミットしたがプッシュ前 | `git reset --soft HEAD~1`（変更は残る） |
| プッシュ済み・PRは未マージ | PR を閉じ、ブランチを捨てて作り直す（**承認が要る**） |
| マージ済み | `git revert <マージコミット>` で打ち消すコミットを積む。**履歴は書き換えない** |
| 実機のアプリが壊れた | 一つ前のコミットでビルドし直して入れ直す |
| シミュレータが変な状態 | `xcrun simctl shutdown <UDID>` のあと再起動 |
| データの移行に失敗（SwiftData） | アプリを消して入れ直す。**記録は消えるので人間の承認が要る** |

**どの戻し方も、実行する前に `progress.md` に「何をしようとしているか」を書いてください。**
戻している最中にセッションが切れると、何が起きたのか誰にも分からなくなります。

## 4. 迷ったとき

判断に迷ったら、**やらずに人間に聞く**。
勝手に進めて取り返しがつかなくなるより、一度止まるほうが安いです。
