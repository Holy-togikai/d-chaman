# voice.md — 日本語の書き方

## 根っこの考え

このアプリの利用者は、**山の中で、手袋をして、急いで**画面を見ます。
読ませる文章ではなく、**見て分かる**画面を作ってください。

## UI の文言

| すること | 例 |
|---|---|
| 短く言い切る | 「歩き出す」「下山する見込み」 |
| 数字を主役にする | 「3:58」が大きく、「登山」は小さく |
| できないことは、できないと書く | 「駐車場の料金と台数は、地図サービスからは取得できません」 |
| 根拠を添える | 「日の入りの1時間前（15:46）に下山する見込みです」 |

| 避けること | なぜ |
|---|---|
| 「〜することができます」 | 長い。「〜できます」で足りる |
| 「エラーが発生しました」 | 何が起きたか分からない。「天気予報を取得できませんでした。通信状況をご確認ください」 |
| 感嘆符 | 山の画面で叫ばれると邪魔 |
| カタカナ語の重ね使い | 「リカバリー」より「やり直し」 |
| 絵文字 | UI にも、コミットにも、PRにも使わない |

**専門用語は使ってよい。** 対象者は登山者です。「コースタイム」「標高差」「体力度」は
そのまま使います。登山の言葉ではなく、**IT の言葉**を避けてください。

## コード内のコメント

**「何をしているか」ではなく「なぜそうしたか」を書く。** コードを読めば何をしているかは分かります。

```swift
// 悪い例：state が .idle のとき開始ボタンを出す
// 良い例：
// 地図で山を選ぶのは、たいてい「いつか登るために調べている」ときです。
// その場で歩き出すことはまずないので、計画を立てるほうを主役にしています。
```

特に、**後から見て「なぜこんな遠回りを？」と思う箇所**には必ず理由を書いてください。
例：`pausesLocationUpdatesAutomatically = false`、`.sheet` を `Form` 直下に置く理由。

## コミットメッセージ

Conventional Commits の形で、**本文は日本語**。

```
feat(Yamatabi): 時間割を自分で決められるようにする

これまで時間割は「日の入りの1時間前までに下山」で固定だった。
日の出と日の入りはあくまで判断の材料として出し、何時に歩き出すかは
利用者が決める形に変えた。

- 自由設定: 歩き出す時刻を自分で決める
- 日の出基準: 日の出のX時間後に歩き出す
```

**何をしたかだけでなく、なぜそうしたかを書いてください。**

## PR の説明

次の見出しを使います。

1. `## 変更` — 何をどう変えたか
2. `## 確認したこと` — **具体的な数値と画面名で**。「動作確認しました」は不可
3. `## 補足` — 残っている問題、やらなかったこと、分かっている限界

**できていないことを隠さない。** 「実機にはインストール済みですが、端末がロック
されていたため起動確認はできていません」のように、正直に書いてください。

## 人間への報告

- 長所を並べる前に、**見つけた不具合を先に**言う
- 「完璧です」「問題ありません」と言わない。何を確かめ、何を確かめていないかを言う
- 自分の失敗は、言い訳せず一行で認めて、次に進む
