# 0003. まず無料で公開し、実績を積んでから買い切りにする。天気は met.no を主にする

- **状態**: 決定
- **決めた日**: 2026-11-27
- **決めた人**: Holy-togikai
- **関係するタスク**: T-006、T-012、T-013、T-014、T-015

## 何を決める必要があったか

公開して保守を続けるには、ある程度の収入が要ります。一方で、課金の形によっては
使っている外部サービスの条件が変わります。特に天気の Open-Meteo は、**無料版が
商用ではない利用に限られ**、有料のアプリや課金機能と両立しません。

## 選べた道

| 案 | 利点 | 欠点 |
|---|---|---|
| 最初から買い切り | すぐ収入が入る | 実績の無いアプリにお金を払う人は少ない |
| 最初から年額の定期課金 | 保守費用を毎年まかなえる | 払い続ける価値を出し続ける必要がある |
| **無料で公開し、実績を積んでから買い切り** | 使ってもらいながら改善できる。課金の仕組みはサーバー不要で作れる | しばらく収入は無い |
| 広告 | 実装が簡単 | 山の画面が狭くなる。オフラインでは出ない。収入も小さい |

## 決めたこと

1. **まず無料で公開する。** ある程度の実績（利用者・評価）を積んでから、**買い切りの有料機能**に切り替える
2. **天気の主な提供元を met.no（MET Norway）にする。** Open-Meteo は控えに回す

## なぜそう決めたか

- 実績の無いうちは、無料で使ってもらって改善するほうが早い
- 買い切りは Apple の仕組み（StoreKit）だけで作れ、サーバーを持たずに済む
- met.no は出典を表示すれば**商用でも無料**。有料化したあとも同じ作りで使い続けられる

## この判断の結果どうなるか

### 天気

- met.no が主、Open-Meteo が控え（`WeatherService.forecast`）
- met.no は**日本向けの降水確率を出さない**ので、雨量（mm）で表示する。確率が出るのは控えから取れたときだけ
- met.no の規約に合わせ、返ってきた「Expires」の時刻までは同じ地点を取りに行かない（`MetNoCache`）
- **有料版に切り替える前に、`WeatherService.usesOpenMeteoFallback` を false にするか、
  Open-Meteo の商用プランを契約すること。** 無料で公開している間は控えとして残す

### 公開の前に人間が決めること・すること

| こと | 理由 |
|---|---|
| Apple Developer Program への登録（年99ドル、決済と本人確認） | App Store に出すのに必須 |
| アプリ用の連絡先（メールアドレス） | met.no の規約で、アプリから連絡先を示すことが求められている。サポートページにも要る |
| GitHub リポジトリを private にするか | 有料化の前に仕組みを見せたくない場合。**権限の変更なので人間が行う** |
| 登山コースのデータ（各県のグレーディング表）を使ってよいかの確認 | 県が公表した表から作ったデータ。アプリで配る形に問題がないか、各県の利用条件を確かめる |

### 有料化のときに見直すこと

- Open-Meteo の扱い（上の太字）
- 登山コースのデータの利用条件（有料アプリでの利用）
- 国土地理院へは「無料／一部有料機能」と伝えたうえで回答を得ている（決定記録 0001）ので、出典表示と私的利用の範囲を守れば変わらない

## 根拠

- [Open-Meteo 利用規約](https://open-meteo.com/en/terms): 無料の API は商用ではない利用に限る
- [MET Norway の利用条件](https://api.met.no/doc/TermsOfService): 出典表示と名乗り（User-Agent）が条件
- [App Store Small Business Program](https://developer.apple.com/app-store/small-business-program/): 年間売上100万ドル以下なら手数料15%
