# mission.md — 何を作るのか

## 1. 最終的な完成品

iPhone 向け登山アプリ **「山旅（Yamatabi）」** を App Store で公開すること。

登山の**出発から帰宅まで**を一本で支えるアプリです。既存アプリ（YAMAP など）は
記録と地図が中心で、前後の段取りが手薄だという不満が出発点になっています。

完成品の定義：

- App Store の審査を通り、一般に公開されている
- 下の「対象者」が、計画から記録、帰路の寄り道まで、このアプリだけで完結できる
- 有料機能が動いている（課金は Phase 5）

## 2. 対象者

**主たる対象者**は、作者本人を含む、次のような人です。

- 自家用車で登山口まで行き、日帰りで登る人
- 登山歴があり、コースタイムや標高差という言葉が分かる
- 事前の段取り（出発時刻、駐車場、ごはん、帰りの温泉）を自分で調べるのが面倒だと感じている
- iPhone を使っている

**対象に含めない人**（いまは作らない、という宣言です）：

- 山小屋泊・縦走など、複数日の行程を組む人
- 公共交通機関で登山口へ向かう人（バスの時刻表データを持っていないため）
- 海外の山に登る人（山岳データも日の出計算も日本向け）
- Android を使っている人

**仮定**：対象者像は作者本人の使い方から立てています。他の利用者への聞き取りは
まだ行っていません。公開前に確かめる価値があります。

## 3. 完成までの段階

| Phase | 内容 | 状態 |
|---|---|---|
| 1 | 山を選ぶ → 地図表示 → GPS で記録 | 記録まで完了。**オフライン地図が未着手** |
| 2 | 登山計画・出発時刻の逆算・天気・駐車場 | 完了 |
| 3 | 下山後のおすすめ（温泉・食事処・道の駅） | 完了 |
| 4 | 山ごはん（レシピ・買い出しリスト） | 完了 |
| 5 | App Store 公開・課金 | 未着手 |

各 Phase の細かい進捗は `Apps/Yamatabi/README.md` にあります。

## 4. 役割

最大3つ。ひとりのAIが順にこなしても構いませんが、**役を切り替えたことを宣言**してください。

### 計画役

| 項目 | 内容 |
|---|---|
| 担当する | 要望を小さなタスクに割る。順番と依存関係を決める。`tasks.json` を書く。完成条件（`passes`）を決める |
| 担当しない | **コードを書かない。** ビルドしない。合否を決めない |
| 最初に読む | `docs/mission.md` / `docs/requirements.md` / `tasks.json` / `progress.md` |
| 使える道具 | ファイルの読み取り、`git log`、Web検索 |
| 返すもの | 更新された `tasks.json`（新しいタスクに `id` `task` `passes` `dependencies` が埋まっている） |
| 完了条件 | 新しいタスクすべてに、**証拠の取り方まで書かれた** `passes` がある |

### 実行役

| 項目 | 内容 |
|---|---|
| 担当する | コードを書く。ビルドする。シミュレータで動かす。証拠を集める。コミットとPRを作る |
| 担当しない | **自分の仕事に合格を出さない。** タスクを増やさない（気づいたことは `progress.md` に書く）。完成条件を書き換えない |
| 最初に読む | `AGENTS.md` / `tasks.json` の当該タスク / `docs/voice.md` / `evals/acceptance.md` |
| 使える道具 | 全部（編集・ビルド・シミュレータ・実機・`gh`） |
| 返すもの | コミット済みのコード、PR、`evidence` に書いた証拠、`progress.md` への追記 |
| 完了条件 | `passes` のすべての項目に対して証拠を出し、`status` を `review` にした |

### 検品役

| 項目 | 内容 |
|---|---|
| 担当する | 証拠を見て合否を決める。足りない証拠を指摘する |
| 担当しない | **自分で直さない。** タスクを書き換えない |
| 最初に読む | `evals/acceptance.md` / `tasks.json` の当該タスク / 実行役が出した証拠 |
| 使える道具 | ファイルの読み取り、`git diff`、ビルドの再実行、シミュレータでの再確認 |
| 返すもの | 合否と理由。不合格なら、何の証拠が足りないか |
| 完了条件 | `status` を `done`（合格）または `in_progress`（差し戻し）に戻した |

**検品役は、実行役の「できました」を合格理由にしてはいけません。**
証拠そのものを見てください。証拠が無ければ、それだけで不合格です。
